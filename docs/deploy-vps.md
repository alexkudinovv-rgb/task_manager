# Выкладка на VPS

## Что настроено

- CI: TypeScript, тесты с PostgreSQL (включая интеграционные), сборка фронта и Docker.
- Actions → **Deploy to VPS** → Run workflow → ветка **main**. Другие ветки не выкладываются.
- Деплой повторяет CI для того же коммита, затем собирает образ и передаёт его по SSH.
- Образ содержит настоящий HTTP-клиент, без VITE_DEMO. Реестр образов не требуется.
- PostgreSQL и приложение доступны только внутри Docker; наружу опубликованы 80/443 Caddy.
- БД, локальные вложения и сертификаты сохраняются в именованных томах проекта `car-city`.
- Перед миграциями сохраняется `pg_dump`; успешность деплоя проверяется healthcheck приложения и запросом к БД.

## Первичная подготовка VPS

Нужны Linux x86_64, Bash, `flock`, Docker Engine и Compose plugin v2 с поддержкой
`up --wait` (рекомендуется актуальная версия). Сборка выполняется на GitHub runner.
Создайте отдельного пользователя для деплоя с доступом к Docker. Учтите: доступ
к Docker фактически даёт права root на VPS. Добавьте публичную часть отдельного
SSH-ключа в его authorized_keys. Workflow использует SSH на порту 22.

Создайте у этого пользователя `~/car-city/.env` по `deploy/.env.example`, права 600.
Не копируйте реальные секреты в репозиторий и не присылайте их в чат.

- APP_DOMAIN — домен без схемы и пути; PUBLIC_URL — тот же домен с https://.
- POSTGRES_PASSWORD: `openssl rand -hex 32`. Тот же пароль впишите в DATABASE_URL.
- TOTP_ENCRYPTION_KEY: `openssl rand -base64 32`. Сохраните ключ: его смена ломает
  расшифровку уже зарегистрированных TOTP-секретов.
- Для пушей добавьте сгенерированную пару VAPID-ключей. Не меняйте её при каждом релизе.
- Для S3 задайте FILE_STORAGE=s3 и параметры из примера. В режиме local вложения
  находятся в Docker-томе uploads и требуют отдельного резервного копирования.
- MCP_DEV_KEY оставьте незаданным: это демонстрационный MCP с общей авторизацией.

Укажите A-запись домена на VPS; AAAA — только при работающем IPv6. Разрешите входящие
22/80/443. Порты 80/443 должны быть свободны. Caddy автоматически получает HTTPS-сертификат.
Под существующий reverse proxy конфигурацию нужно адаптировать перед запуском.

В GitHub Settings → Environments создайте `production`. Если тариф позволяет,
добавьте required reviewers и разрешите деплой только main. Сам workflow запускается вручную.
Добавьте environment secrets:

| Имя | Значение |
|---|---|
| VPS_HOST | IP или DNS-имя VPS |
| VPS_USER | Пользователь деплоя |
| VPS_SSH_KEY | Приватная часть отдельного SSH-ключа |
| VPS_KNOWN_HOSTS | Строка host key для указанного VPS_HOST, сверенная через консоль провайдера |

Не доверяйте результату ssh-keyscan без независимой проверки fingerprint.
Секреты БД, S3 и TOTP остаются только в .env на VPS.

## Первый запуск

Запустите workflow из main. В конце проверьте `https://<домен>/api/health` и вход
через браузер: внутренний healthcheck не проверяет DNS и внешний TLS.
Создайте собственника на VPS интерактивной командой из каталога нужного релиза:

```bash
export APP_ENV_FILE="$HOME/car-city/.env"
export APP_IMAGE="car-city:$(cat "$HOME/car-city/current-release")"
docker compose --project-name car-city --env-file "$APP_ENV_FILE" -f compose.yml exec app npm run create-owner -w apps/server
```

Не направляйте приложение на существующую БД со стенда без отдельного плана переноса.
Этот Compose создаёт новую БД. Пароль POSTGRES_PASSWORD применяется при её первой
инициализации; изменение .env само по себе пароль существующей БД не меняет.

## Ошибка обновления и восстановление

Релизы: `~/car-city/releases/<sha>`, текущий успешный SHA: `~/car-city/current-release`.
Бэкап перед обновлением: `~/car-city/backups/<UTC-время>-<sha>.dump`.
Бэкап создаётся и при первом запуске (пустая БД). Автоматического удаления копий и образов нет:
контролируйте свободный диск и настройте срок хранения после выбора внешнего хранилища.

При ошибке workflow останавливается, но не гарантирует продолжение работы старой версии:
Compose обновляет один экземпляр приложения, поэтому возможен перерыв в работе.
Автоматического отката БД нет. Сначала изучите логи `docker compose ... logs app`.
Миграции запускаются существующим Docker CMD перед стартом приложения.

Для отката кода выберите предыдущий сохранённый образ `car-city:<sha>` и конфигурацию
того релиза. Запускайте его только после проверки совместимости со схемой БД.
Если нужна старая схема, восстановите dump в отдельную БД и проверьте её до переключения.
Не выполняйте `docker compose down -v`: это удаляет БД, вложения и сертификаты.

Копия перед деплоем не заменяет ежедневные внешние бэкапы БД и вложений.
Их расписание, удалённое хранилище и проверка восстановления настраиваются отдельно.
