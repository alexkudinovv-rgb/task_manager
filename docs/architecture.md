# Таск-менеджер Car City — архитектура и площадка (CC-231)

Статус: черновик решений, которые зависят от нас. Хостинг и домен ждут ответа Григория — см. раздел «Открытые вопросы».

## Коротко о системе

Таск-менеджер — одно веб-приложение: на телефоне оно ставится как PWA, на компьютере открывается как обычный сайт. Интерфейс — React-приложение, сервер — Node.js на TypeScript, данные — PostgreSQL, файлы — S3-совместимое хранилище у того же российского провайдера. На сервере в одном процессе работают API, чаты в реальном времени, Telegram-бот, фоновые задачи (напоминания о сроках, дневные сводки) и MCP-сервер для ChatGPT и Claude. Всё упаковано в Docker и запускается одной командой.

Обновление без консоли: код лежит в git, при каждом push в основную ветку CI собирает образ и сам выкладывает его на тестовый контур. На боевой контур выкладка идёт кнопкой в CI после проверки на тесте. Базу каждую ночь копируем в хранилище у другого провайдера; восстановление проверяется скриптом раз в месяц.

## Решения

### Стек

| Слой | Выбор | Почему |
|---|---|---|
| Язык | TypeScript везде | Один язык на фронте и бэке, общие типы для API. Текущий сайт тоже на TS/Next.js. |
| Фронт | React + Vite, `vite-plugin-pwa` | SEO не нужно (наоборот, закрываемся), SSR не нужен. SPA проще всего делать PWA с офлайн-кешем. |
| Сервер | Node.js 24 LTS + Fastify | Нужен постоянно живущий процесс: WebSocket-чаты, бот, фоновые задачи. Next.js для этого неудобен. |
| БД | PostgreSQL 17 | Транзакции, частичные уникальные индексы (одна горящая задача на человека — CC-234), полнотекстовый поиск по архиву на русском (CC-233). |
| ORM / миграции | Drizzle ORM | Типобезопасно, миграции SQL-файлами в репозитории. |
| Очередь и крон | pg-boss (поверх PostgreSQL) | Напоминания, сводки, дедупликация уведомлений без отдельного Redis. |
| Реалтайм | WebSocket (`@fastify/websocket`) | Пользователей единицы и десятки — хватит одного экземпляра сервера. |
| Файлы | S3-совместимое хранилище провайдера | Вложения в задачах и чатах, не в базе и не на диске VPS. |
| Telegram | grammY | Бот собственника (CC-237), привязка аккаунта deep-link'ом из профиля. |
| MCP | `@modelcontextprotocol/sdk`, Streamable HTTP | Отдельный путь `/mcp` того же сервера, доступ по ключу пользователя (CC-241). |
| Веб-сервер | Caddy | HTTPS-сертификат автоматически, заголовки noindex на всё (CC-242). |

Дизайн: токены из руководства Car City (холст `#F1F2F4`, графит `#17181B`, сигнал `#FFB700`, шрифты Unbounded / Onest / JetBrains Mono, тени `--shadow-card`) переносим CSS-переменными один в один. Экраны — по согласованному макету из Claude Design.

### Окружения

Решение Григория (20.10.2026): требование про российский хостинг касается только боевой версии. Тестовую выкладываем на GitHub Pages.

| | Тестовый | Боевой |
|---|---|---|
| Где | GitHub Pages, `https://<аккаунт>.github.io/<репозиторий>/` | российский хостинг, `<домен>` |
| Что работает | только интерфейс на подставных данных (`apps/web/src/api/mock.ts`) | всё: сервер, база, вход, чаты, уведомления, MCP |
| Данные | вымышленные, реальных людей и задач нет | реальные |
| Выкладка | автоматически на каждый push в `main` (`.github/workflows/pages.yml`) | кнопкой в CI |
| Доступ | открыт всем, у кого есть ссылка; поисковики закрыты `robots.txt` и `noindex` | вход с 2FA |

Ограничения тестовой версии:

- Pages отдаёт только статические файлы, поэтому вход, 2FA, чаты, пуши, Telegram и MCP на нём не проверить. Серверную часть до появления хостинга проверяем локально.
- Сайт на Pages публичный (на бесплатном тарифе GitHub публичен и сам репозиторий). Поэтому никаких реальных имён, телефонов и задач в подставных данных и в репозитории быть не должно.
- Когда появится боевой хостинг, решим, нужен ли рядом с ним полноценный тестовый контур с сервером.

Интерфейс общается с данными только через контракт `TaskApi` (`apps/web/src/api/index.ts`). Подставная реализация заменяется HTTP-клиентом без изменения экранов.

Секреты хранятся в CI и в `.env` на сервере, в репозиторий не попадают.

### Резервные копии

- `pg_dump` каждую ночь → S3-хранилище **у другого провайдера или в другом регионе**, чтобы падение одного провайдера не забрало и копии.
- Хранение: 14 ежедневных + 8 еженедельных копий.
- Бакет с вложениями — с версионированием.
- Скрипт восстановления разворачивает последнюю копию в чистую базу и проверяет, что задачи читаются. Запускаем вручную при сдаче CC-231, дальше раз в месяц по расписанию.
- Снапшоты VPS у провайдера — дополнительная страховка, не основная.

### Что закладываем сразу, хотя понадобится позже

- **Журнал событий задачи** (создана, назначена, статус сменился, первая реакция, закрыта) с меткой времени — без него нечего будет показывать на экране пульса (CC-238).
- **Статусы и переходы — данными, а не кодом**: таблица «статус → куда можно перейти → какой роли разрешено». Ответы опросника заполнят её без переписывания.
- **`/mcp` должен быть доступен из интернета** (к нему ходят серверы OpenAI и Anthropic), поэтому ограничение по IP на весь сервер не ставим. Без авторизации сервер отдаёт только форму входа (CC-242), а `/mcp` — 401.
- **Персональные данные** сотрудников (ФИО, телефоны, Telegram) хранятся только на российском хостинге (152-ФЗ). Railway, где сейчас живёт сайт, для этого не подходит.

## Требования к хостингу (для выбора провайдера)

- Дата-центр в РФ.
- VPS: боевой — от 2 vCPU / 4 ГБ / 40 ГБ SSD, тестовый — 2 vCPU / 2 ГБ.
- S3-совместимое объектное хранилище.
- Снапшоты дисков.
- Оплата с юрлица (если нужно бухгалтерии).

Подходят, например: Selectel, Timeweb Cloud, Yandex Cloud, VK Cloud. Резервные копии лучше держать у другого провайдера из этого списка.

## Домен

- Зона `.ru`, как в задаче.
- Предлагаю **нейтральное имя, не связанное с брендом** (не `tasks.car-city.ru`): систему проще спрятать, если домен ни с чем не ассоциируется и не всплывает в поиске по названию компании.
- Регистрация на юрлицо или на доверенное физлицо — решает Григорий. Важно, чтобы доступ к регистратору был у компании, а не только у разработчика.
